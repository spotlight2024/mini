# Selenium Grid 部署总结

## 🎯 系统概述

本系统是一个基于 Kubernetes 的 Selenium Grid 集群，具备以下特性：

- **自动扩容**: 基于 KEDA 的智能扩容，根据活跃会话数自动调整节点数量
- **透明代理**: 集成 tinyproxy，支持透明代理功能
- **高可用**: 多节点部署，支持会话负载均衡
- **易维护**: 完整的运维工具链和文档

## 🏗️ 架构设计

### 核心组件
```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   Selenium Hub  │    │  Chrome Nodes   │    │   KEDA + HPA    │
│   (控制中心)     │◄──►│   (浏览器节点)   │◄──►│   (自动扩容)     │
└─────────────────┘    └─────────────────┘    └─────────────────┘
         │                       │                       │
         ▼                       ▼                       ▼
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   Web UI        │    │  tinyproxy      │    │   Metrics API   │
│   (管理界面)     │    │  (透明代理)     │    │   (指标接口)     │
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

### 扩容逻辑
- **基础容量**: 3 个常驻节点
- **扩容策略**: `目标节点数 = 活跃会话数 + 2`
- **最大容量**: 100 个节点
- **响应时间**: 5 秒轮询，180 秒冷却期

## 📊 资源配置

### 节点规格
| 资源类型 | 请求 | 限制 | 说明 |
|----------|------|------|------|
| CPU | 500m | 2 | 支持并发测试 |
| 内存 | 1536Mi | 2Gi | 包含 Chrome 和代理 |
| 共享内存 | - | 2Gi | 提升 Chrome 性能 |
| 存储 | 1Gi | 1Gi | 用户数据目录 |

### 集群规模
- **最小规模**: 3 节点（基础容量）
- **推荐规模**: 10-20 节点（生产环境）
- **最大规模**: 100 节点（峰值负载）

## 🚀 部署流程

### 1. 环境准备
```bash
# 检查集群状态
kubectl cluster-info
kubectl get nodes

# 准备镜像
docker pull selenium/hub:latest
docker pull chrome-tinyproxy-node:latest
```

### 2. 一键部署
```bash
cd mini/docker/k8s
./quick-deploy.sh
```

### 3. 功能验证
```bash
# 检查服务状态
kubectl -n selenium-grid get all

# 测试扩容功能
python3 test_scaling.py

# 访问管理界面
open http://172.16.1.129:30444
```

## 🔧 关键配置

### 网络配置
- **Hub 端口**: 30444 (对外访问)
- **内部通信**: 4442, 4443 (Event Bus)
- **VNC 端口**: 5900, 7900 (调试用)

### 代理配置
- **代理类型**: tinyproxy (容器内)
- **代理端口**: 8888
- **透明代理**: 自动配置环境变量

### 扩容配置
- **指标源**: 自定义指标导出器
- **指标接口**: `/value` 端点
- **扩容算法**: 线性扩容

## 📈 性能指标

- **单节点**: 1 个并发会话

- **扩容速度**: 5 秒/批次
